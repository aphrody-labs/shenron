# Exécution Shenron

Appliquer `~/.codex/YOLO-NHITL.md` lorsqu'il est disponible. Sinon, terminer
le lot autorisé sans confirmation intermédiaire : consulter les règles du dépôt,
préserver le travail concurrent, valider, livrer avec l'identité propriétaire.
Les gates et l'autorité du domaine restent obligatoires.

Shenron relève du monorepo Aphrody. Lire le [snapshot propriétaire](upstream-main.md)
et vérifier la surface concernée dans le checkout actif avant d'utiliser une
commande. Charger uniquement la référence utile ; les relevés datés ne prouvent
ni l'état du service ni le contenu actuel du corpus.

Le MCP installé déclare `aphrody-mcp server` (stdio). La disponibilité réelle
vient de `tools/list`, pas du manifeste. Préférer les outils natifs exposés,
puis le CLI propriétaire avec son aide actuelle. Les préfixes affichés varient
selon le fournisseur ; utiliser le nom et le schéma effectivement reçus.

Une maintenance de plugin ne donne aucun droit de production. Une écriture
éditoriale, une commande Discord ou une action de service exige une demande
couvrant cet effet et l'authentification officielle ; cette autorisation acquise,
exécuter avec contrôles techniques sans nouvelle confirmation. En cas de donnée
ou d'autorité manquante, livrer la proposition et préciser la limite.

Les secrets restent dans l'environnement protégé : jamais dans les prompts,
arguments, URLs, plugin, reçus ou journaux. Les lecteurs et traducteurs proposent ;
Shenron possède la validation et le dépôt versionné. PostgreSQL est la source
éditoriale ; SQLite est le réplica du bot. Aucun accès direct à la base depuis
le plugin ni contournement des révisions. La publication reste une décision propriétaire.
