# Base UI to GPUI Kit: full parity matrix

Date: 2026-11-19. Companion of [base-ui-vers-gpui.md](base-ui-vers-gpui.md) (phases and decision). Written in English because every API name is copied from source. Base UI 1.9.0 (live pages on base-ui.com) against gpui-kit 0.10.0 (longbridge/gpui-kit head 390a485aba, built on gpui-pre =0.3.12). Rows analysed with default features only; this repository enables gpui-fast, so re-check a row before relying on it for a spike.

Totals over 37 components: full 4, partial 28, missing 5.

Part A covers accordion to meter, part B navigation-menu to tooltip. Where this matrix disagrees with the first version of the plan, the matrix wins and the plan carries the correction.

# Part A

Sources, all read in this session:
- Base UI: `https://base-ui.com/react/components/<name>.md` (fetched live, 19 pages).
- GPUI Kit: `github.com/longbridge/gpui-kit` head `390a485aba2e8ab92754a23b84eecedf4155b562` (shallow clone), crates `gpui-base` 0.10.0 (`crates/base/src`) and `gpui-component` 0.10.0 (`crates/component/src`). Paths below are relative to `crates/`.
- GPUI itself: gpui-kit pins `gpui = { package = "gpui-pre", version = "=0.3.12" }` (workspace `Cargo.toml:69`), read from the local registry copy `gpui-pre-0.3.12`. The shenron workspace enables the `gpui-fast` feature (`Cargo.toml:168` of the shenron workspace), which swaps GPUI for `gpui-fast` 0.1.17; this report analyses the default-feature code, and `cfg(feature = "gpui-fast")` branches were not compared.
- Status scale: full = every behaviour-changing Base UI prop/part has an equivalent or is meaningless on a native canvas; partial = core works, gaps named; missing = no module in either crate (directory listings of `base/src` and `component/src` checked).
- Effort: S under a day, M days, L a week or more.

## Cross-cutting facts (apply to every row)

- State model: GPUI Kit base parts are controlled and stateless (`open(bool)`, `checked(bool)`, handler `on_change`/`on_open_change`); there is no `defaultOpen`/`defaultChecked`/`defaultValue` uncontrolled mode anywhere in the components of this part, except `DialogHandle` (holds its own open flag, `base/src/dialog.rs:35`) and the entity-backed states (`InputState`, `ComboboxState`). Base UI's controlled/uncontrolled duality maps to "application owns the bool" in GPUI.
- Data attributes (`data-open`, `data-checked`, `data-disabled`, `data-starting-style`...) have no equivalent: state is passed as builder args (`StateStyle`, `*Styles::checked(..)` in `base/src/checkbox.rs:205`, `base/src/button.rs:196`). Animation is done with `motion` (`spring`, `MotionReveal`, `Presence`) instead of `data-starting-style`/`data-ending-style`.
- Accessibility: GPUI core exposes `role()`, `aria_label`, `aria_expanded`, `aria_toggled`, `aria_selected`, `aria_active_descendant`, `aria_level`, `aria_position_in_set`, ... (`gpui-pre-0.3.12/src/elements/div.rs:1357-1540`) feeding AccessKit. There is no `aria_disabled`: `base/src/a11y_disabled.rs:1-3` says so and wraps the root to write disabled on the node. `a11y_disabled` is used in `button.rs`, `checkbox.rs`, `select.rs`, input base; it is not used in `accordion.rs`, `dialog.rs`, `component/src/menu/menu_item.rs` (grep count 0), so disabled state of those parts is not projected to assistive technology.
- Keyboard activation: any element with a focus handle and `on_click` gets Enter/Space click (`gpui-pre-0.3.12/src/elements/div.rs:3085-3135`, emits `ClickEvent::Keyboard`). Elements without `track_focus`/`focusable()`/`tab_index` are not focusable.
- Test helpers: `.test_support()` (`base/src/observe.rs`, `base/src/test_support.rs`: `ElementSnapshot` with `role/checked/indeterminate/selected/expanded/value/disabled/label/focused/bounds`, `find`, `find_all`, `snapshots`), `gpui::test` + `simulate_click`/`simulate_keystrokes` (used throughout the module tests). Feature `test-support`.
- Reduced motion: `base/src/reduce_motion.rs` (`ReduceMotionPreference`, `set_reduce_motion_preference`, `apply_system_reduce_motion`), read by components as `cx.reduce_motion()` (e.g. `component/src/accordion.rs`, dialog `entrance`).
- Native a11y adapters (from manifests, not the plan): `gpui-pre-windows-0.3.12/Cargo.toml:55-60` (`accesskit` 0.24.0, `accesskit_windows` 0.34), `gpui-pre-linux-0.3.12/Cargo.toml:47-89` (`accesskit_unix` 0.22 under `wayland`/`x11`), `gpui-pre-macos-0.3.12/Cargo.toml:62-67` (`accesskit_macos` 0.26). Same three in `gpui-fast-*` 0.1.17 (Cargo.toml). `gpui-pre-web-0.3.12` and `gpui-fast-web-0.1.17`: no `accesskit` in Cargo.toml or `src/` (only an `ime_mirror.rs` for text input).
- Web ARIA mirror hook: `PlatformWindow` has default no-op `a11y_init`, `a11y_tree_update(&self, TreeUpdate)`, `a11y_update_window_bounds` (`gpui-pre-0.3.12/src/platform.rs:1441-1447`); web window does not override them. One generic mirror implemented there would serve every role below; per-component work is then only to make sure roles/names/values are set (rows say what is not).

## accordion

- Base UI: Root `value[]`/`defaultValue`/`onValueChange`, `multiple`, `disabled`, `keepMounted`, `hiddenUntilFound`; `loopFocus`/`orientation` deprecated (no roving focus, APG update). Item `value`, `onOpenChange`, `disabled`. Header renders `h3`. Trigger renders `button`. Panel `keepMounted`, `hiddenUntilFound`, CSS var `--accordion-panel-height`. Data attrs: `data-panel-open`, `data-open`, `data-disabled`, `data-index`, `data-orientation`, `data-starting-style`, `data-ending-style`. Change reasons: `trigger-press`, `none`.
- GPUI base (`base/src/accordion.rs`): `Accordion::new(id)` (Role::Group, line 58); `AccordionItem::{open, disabled, header, panel}` (79-110); `AccordionHeader::{new(trigger), level, id}` (Role::Heading + `aria_level`, 188-205); `AccordionTrigger::{new(id), open, disabled, on_change(Fn(bool,&ClickEvent,..))}` (Role::Button + `aria_expanded`, 344-360); `AccordionPanel::{open, keep_mounted, id}` (Role::Region, 255-275). `on_change` receives the requested next state; the app applies it.
- GPUI component (`component/src/accordion.rs`): `Accordion::{multiple, bordered, disabled, item(|AccordionItem| ..), on_toggle_click(Fn(&[usize],..))}` (46-80); items carry `icon/title/open/disabled/title_style/content_style`; open/close animated by `spring` + `MotionReveal`, panel unmounts when settled (render, ~lines 290-340); reduced motion respected.
- Parity gaps:
  - No uncontrolled mode, no `value` identity: items are addressed by index (`on_toggle_click` reports `&[usize]`); the single-open rule is enforced in a per-render `Rc<RefCell<HashSet>>` (line ~100), the app must still feed `.open()` back.
  - No Root-level `onValueChange` with reason, no per-item `onOpenChange` on the component API (only the base trigger `on_change`).
  - Trigger is not focusable by itself: `AccordionTrigger` never calls `track_focus`/`focusable()` (grep over `base/src/accordion.rs`, `component/src/accordion.rs`: no `focusable`, `tab_stop`, `track_focus` call), so Tab/Enter/Space reach it only if the app adds a focus handle. `InteractiveElement::track_focus` is exposed on it (line 331).
  - Disabled is not written to the accessibility node (no `a11y_disabled`).
  - No `aria-controls`/`aria-labelledby` between trigger and panel (no equivalent setter used; Role::Region panel has no label).
  - `hiddenUntilFound`: N/A (no browser find-in-page on a canvas).
  - Orientation/loop: deprecated in Base UI, nothing to match.
- Fix: local wrapper in `shenron-theme` that adds `focusable()`/tab index and `a11y_disabled` around `AccordionTrigger`; upstream PR to make `AccordionTrigger` focusable by default (small, matches Base UI `button`). Effort S.
- Web: roles Group/Heading(level)/Button(expanded)/Region need the ARIA mirror; Region has no name.

## alert-dialog

- Base UI: parts Root, Trigger, Portal, Backdrop, Viewport, Popup, Title, Description, Close, `createHandle`/Handle. Root `open`/`defaultOpen`/`onOpenChange`, `handle`, `triggerId`/`defaultTriggerId`, `actionsRef`, `onOpenChangeComplete`. Popup `initialFocus`, `finalFocus`. No `modal` and no `disablePointerDismissal` props (always modal, outside press does not dismiss). Reasons: `trigger-press`, `outside-press`, `escape-key`, `close-press`, `focus-out`, `imperative-action`, `none`.
- GPUI base (`base/src/alert_dialog.rs`): `AlertDialog` wraps `Dialog` with `Role::AlertDialog` and `close_on_backdrop_press(false)` (lines 195-201); `open`, `handle(DialogHandle)`, `on_open_change(Fn(bool, DialogChangeReason,..))`, `backdrop`, `popup`, `close_on_escape`, `dismiss_below_y`, `on_ok/on_cancel/on_close`; parts `AlertDialogBackdrop/Popup/Title/Description/Trigger/Action/Cancel/Close`. Focus trap via `focus_trap` inside `Dialog`. `DialogChangeReason` = `TriggerPress | BackdropPress | Cancel | Confirm | Imperative` (`base/src/dialog.rs:26`).
- GPUI component (`component/src/dialog/alert_dialog.rs`): `AlertDialog::{new, confirm, trigger, content, footer, icon, title, description, ok_text, cancel_text, ok_variant, cancel_variant, show_cancel, close_button, keyboard, width, centered, entrance, on_ok/on_cancel/on_close}`; `overlay_closable(self, _: bool)` is an explicit no-op (line 248); opened with `window.open_alert_dialog` (`component/src/window_ext.rs:101`). Focus is restored to the previously focused handle by `Root` (`component/src/root.rs:60,400`).
- Parity gaps:
  - Enter is bound to `Confirm` in the `Dialog` key context (`base/src/dialog.rs:89-94`) and closes the dialog through `on_ok`; Base UI does not close on Enter. Behavioural difference, probably desirable for alerts.
  - No `initialFocus` (the host takes focus; `focus_handle(..)` is `#[doc(hidden)]`), no `finalFocus` override, no `onOpenChangeComplete`, no `actionsRef`.
  - Handle carries no payload and cannot be shared by several triggers with different content; `DialogHandle` is app-local state.
  - `Role::AlertDialog` is set; no description relationship (`aria-describedby`) is emitted, only `accessibility_label` (name) exists on `Dialog` (`base/src/dialog.rs:496`).
- Fix: compose from existing modules; add `initial_focus(&FocusHandle)` upstream or a wrapper; S.
- Web: Role::AlertDialog + label via mirror; focus trap is implemented in GPUI (`FocusTrapManager`), a DOM mirror must not add its own trap.

## autocomplete

- Base UI: free-form text input plus suggestion list (`Combobox` is selection-restricted, Autocomplete is not). Root `value`/`defaultValue`/`onValueChange`, `open`, `mode` (`list`|`both`|`inline`|`none`: filtering and inline completion), `autoHighlight`, `keepHighlight`, `highlightItemOnHover`, `filter`, `filteredItems`, `items`, `limit`, `loopFocus`, `modal`, `grid`, `inline`, `openOnInputClick`, `submitOnItemClick`, `virtualized`, `onItemHighlighted`, `itemToStringValue`, `name/form/required/readOnly/disabled`. Data attrs on Input/Popup/Item (`data-popup-open`, `data-highlighted`, `data-side`, ...).
- GPUI: no module (`base/src` and `component/src` listings checked: only `combobox`, `select`, `command`, `list`, `searchable_list`, `input`). `ComboboxState` stores a selection of delegate items, not free text; its `query` is separate (`set_query`/`query`, `component/src/combobox.rs:410-415`). The editor popovers in `component/src/input/popovers/completion_menu.rs` are LSP-oriented for `Editor`, not a general single-line suggestion API (not read in detail; unverified for reuse).
- Fix: compose `Input` (events `Change`, `PressEnter`, `base/src/input/base/state.rs:139`) + `Popover` + `list::List` with `SearchableListDelegate::perform_search` for async filtering (`component/src/searchable_list/delegate.rs:97`); keyboard: List binds only up/down/enter/escape (`component/src/list/list.rs:29-40`). Needs: inline completion (`mode: both/inline`), `aria_active_descendant` on the Input pointing at the highlighted option, `Role::ComboBox`. Upstream PR to longbridge/gpui-kit preferred (a `free_text` option on `Combobox` is the smallest diff); local wrapper in `shenron-theme` otherwise. Effort M.
- Web: needs ARIA mirror with combobox + listbox + active-descendant; the Input already has a web `ime_mirror` (text only).

## avatar

- Base UI: Root; Image `onLoadingStatusChange`, `keepMounted`; Fallback `delay` (ms). Image is preloaded and shown only after load; Fallback shows on error or no image. Data attrs on Image: `data-loading`, `data-error`, `data-starting-style`, `data-ending-style`.
- GPUI base (`base/src/avatar.rs`): `Avatar::{image(AvatarImage), fallback(AvatarFallback)}`; render picks the image if present, else the fallback (lines 57-64). `AvatarImage::new(impl Into<ImageSource>)` wraps `gpui::img` (66-82).
- GPUI component (`component/src/avatar/avatar.rs`): `Avatar::{src, name, placeholder, Sizable}`, initials with name-derived colours (lines 100-145); `AvatarGroup::{child, children, limit, ellipsis}`.
- Parity gaps:
  - No loading status and no fallback on load failure: fallback is shown only when no `src` was given. GPUI's `Img` has `with_fallback`/`with_loading` (`gpui-pre-0.3.12/src/elements/img.rs:162,169`) but `AvatarImage` does not use them. No `delay`, no `onLoadingStatusChange`.
  - No accessible name in production: the component feeds `name` to `test_alt_text`, which is a no-op without the `test-support` feature (`base/src/observe.rs:67-77`). The avatar has no role/label for assistive technology.
- Fix: upstream PR (wire `with_fallback` + `Role::Image` + `aria_label(name)`); or local wrapper adding `aria_label`. Effort S.
- Web: needs `Role::Image` with name through the mirror; currently nothing to mirror.

## button

- Base UI: `disabled`, `focusableWhenDisabled`, `nativeButton`; no `type=submit` default. Data attr `data-disabled`. Keyboard: Enter/Space (native).
- GPUI base (`base/src/button.rs`): `Button::{new(id), disabled, selected, styles(ButtonStyles::{selected, disabled}), accessibility_label, role(impl Into<RoleOverride>), track_focus, on_click, tab_index, tab_stop, focusable(bool)}`; Role::Button default, Enter/Space click via GPUI, focus on press; a disabled button swallows mouse-down and leaves the tab order unless it currently holds focus (`button.rs:296`, comment at 72) which covers the documented loading case; `a11y_disabled` at line 332.
- GPUI component (`component/src/button/button.rs`): variants (`ButtonVariants`), `outline`, `rounded`, `label`, `icon`, `tooltip*`, `loading` (inert like disabled, line 552), `compact`, `on_hover`, `aria_expanded`, `toggled`, `dropdown_caret`, `accessibility_id/label`; `ButtonGroup` (`multiple`, `layout`), `DropdownButton`, `Toggle`.
- Parity gaps: `focusableWhenDisabled` has no explicit equivalent (focus is retained only if already focused); no submit semantics (no native `<form>` on a canvas, see form row). `nativeButton` N/A.
- Fix: none for the primitive; submit handled in the Form wrapper. Effort S.
- Web: Role::Button/disabled through the mirror.

## checkbox-group

## context-menu

- Base UI: Root (`open`, `onOpenChange`, `loopFocus`, `disabled`, `orientation`, `highlightItemOnHover`, `onItemHighlighted`, `onOpenChangeComplete`), Trigger (area), Portal, Backdrop, Positioner (side/align/offsets/collision props), Popup (`finalFocus`), Item (`label`, `closeOnClick`, `disabled`), LinkItem, Group/GroupLabel, Separator, SubmenuRoot/SubmenuTrigger (`openOnHover`, `delay`, `closeDelay`), RadioGroup/RadioItem/RadioItemIndicator, CheckboxItem(`checked`, `defaultChecked`, `onCheckedChange`)/Indicator.
- GPUI (`component/src/menu/context_menu.rs`): `ContextMenuExt::context_menu(|PopupMenu, &mut Window, &mut Context<PopupMenu>| PopupMenu)` on any `InteractiveElement + ParentElement + Styled` (lines 17-43); opens on right mouse button (line 406) and on `LongPressEvent` (touch, line 389).
