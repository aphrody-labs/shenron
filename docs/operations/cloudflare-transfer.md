# Copier et vérifier le CDN par S3

La CLI durable cloudflare-transfer reprend le job qualifié de migration. Elle exige le fichier privé d’objets et son SHA256 exact, un manifest de compte/bucket, un répertoire d’état privé et l’origine HTTPS du Worker vérificateur. L’installation passe par Infra SSH : sh install-cli.sh copie les artefacts ; --install-owner-s3 ajoute le code root et les templates après vérification du credential déjà présent, sans créer de credential ni activer un service. register-infra.ts conserve toutes les entrées étrangères et prépare les trois services, deux timers et la tâche locale ; Infra valide et active ensuite les unités.

status lit les reçus locaux sans réseau ni écriture et peut observer un transfert actif. sync --apply téléverse les objets manquants sous _objects/SHA ; verify --apply relit tous les objets via le Worker. Le HEAD de vérification peut attacher les métadonnées après contrôle du corps : verify n’est donc pas une commande strictement RO. Pour sync, fournir chaque racine publique autorisée par --source-root ; les chemins réels doivent y rester, et le corps doit garder exactement taille/SHA de l’inventaire épinglé.

Arguments communs : --manifest FILE --objects FILE --objects-sha256 HASH --state DIR --profile FILE --worker-origin https://WORKER. --limit N borne une qualification ; un succès borné demeure partial:true tant que le catalogue entier n’est pas vérifié. État SQLite WAL, reçus liés au SHA de l’inventaire, verrou exclusif du répertoire, cinq tentatives maximum,64 workers et budget cumulé des corps256MiB. Les corps sont limités à33MiB ; aucune affirmation de consommation RSS totale n’en découle.

Le profil temporaire est relu toutes les quinze secondes ; le client est recréé lorsque credential/sessionToken/expiration change. L’accessKeyId temporaire peut rester identique au parent et ne suffit pas pour détecter un renouvellement. Aucun credential ou URL signée n’est journalisé. Ne pointer aucune nouvelle CLI vers le répertoire du job historique pendant qu’il écrit : son ancien verrou ne partage pas ce contrat. Le job du11octobre reste inchangé.

La preuve complète exige tous les reçus vérifiés pour le manifeste final, puis le contrôle du delta de déploiement et des routes dynamiques. Aucun de ces scripts ne bascule le DNS, ne supprime un objet ou ne certifie une parité DNS par le seul résultat S3.
